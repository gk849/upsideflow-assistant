# Настройка помощника

Человек запустил это в терминале — отвечай в терминале. Ничего не меняй без его «да». Здесь можно писать Markdown.

## 1. Проверка

**CRM Upsideflow.** Найди через ToolSearch инструмент `crm_reference`. Запомни префикс сервера — часть имени до `crm_reference` (обычно `mcp__upsideflow-crm__`).
- Не найден: «CRM Upsideflow для этого аккаунта не подключена. Если вам её не выдавали — это нормально: помощник работает с почтой, календарём и диском. Если доступ должен быть — попросите у администратора Upsideflow инструкцию подключения». Переходи к почте.
- Найден — вызови `crm_reference`:
  - вернул воронки и стадии — ✅ CRM доступна;
  - нужен вход — «Войдите: `/mcp` → upsideflow-crm → Authenticate. На экране согласия проверьте, что «От чьего имени» — ваша почта»;
  - отказ в доступе — «CRM для этого аккаунта не включена — работаем без неё».
- Запись в CRM заранее не проверить, ничего не записав. Объясни: запись включается галочкой «Разрешить запись в CRM через это подключение» на экране согласия при входе. Если при первой записи `crm_confirm` ответит, что запись выключена, — в `/mcp` выйдите из upsideflow-crm, войдите снова и поставьте галочку; показанный предпросмотр после этого можно подтвердить.

**Gmail, Google Calendar, Google Drive.** ToolSearch по «gmail», «calendar», «drive» (до 30 результатов на запрос). Для каждого коннектора запомни префикс сервера и полный список инструментов.
- Не найден: «Подключите на https://claude.ai/customize/connectors и перезапустите Claude Code. Коннекторы claude.ai видны, только если Claude Code вошёл аккаунтом claude.ai — проверьте в `/status`».

**Telegram.** ToolSearch «telegram reply». Есть инструмент вида `mcp__plugin_telegram_telegram__reply` — ✅, запомни точное имя. Нет — «Канал не запущен: установите `telegram@claude-plugins-official`, задайте токен бота (`/telegram:configure <токен>`) и запускайте Claude Code с `--channels plugin:telegram@claude-plugins-official` — см. README плагина».

Итог проверки:

```
Проверка помощника
• CRM Upsideflow — ✅ / не подключена / нужен вход
• Gmail — ✅ / не подключён
• Google Calendar — ✅ / не подключён
• Google Drive — ✅ / не подключён
• Telegram — ✅ / канал не запущен
```

## 2. Правила разрешений — предложение

Зачем: чтение CRM и ответы в Telegram — без лишних вопросов; запись в CRM — всегда с вопросом; отправка и удаление в почте, календаре и диске — запрещены совсем.

Собери три списка из **точных** имён найденных инструментов. Масок не используй: `crm_lead*` захватит `crm_lead_create`, `crm_lead_update`, `crm_lead_move`.

**allow** (только если CRM найдена — с её префиксом; каждое имя отдельно):
- чтение: `crm_reference`, `crm_rules`, `crm_leads`, `crm_lead`, `crm_person`, `crm_dedup_check`, `crm_inbox_list`, `crm_inbox_get`, `crm_lead_files`, `crm_objects`, `crm_object`, `crm_units` (три последних — каталог; добавь, даже если их пока нет в списке: правило для отсутствующего инструмента ни на что не влияет);
- предпросмотры — они ничего не пишут: `crm_lead_create`, `crm_lead_update`, `crm_lead_move`, `crm_activity_add`, `crm_activity_done`, `crm_person_create`, `crm_person_update`;
- Telegram: точное имя инструмента `reply`.

**ask**: `crm_confirm` (с префиксом CRM) — запись всегда с вопросом.

**deny** — у найденных Gmail, Calendar, Drive всё, что не чтение, не поиск и не черновик:
- Gmail: отправка, ответ, пересылка; удаление и корзина писем и веток; спам; метки; фильтры; автоответ. Черновики (создать, изменить, удалить черновик) — не запрещать.
- Calendar: создать, изменить, удалить событие; ответить на приглашение; создать календарь.
- Drive: поделиться, изменить доступ, переместить, переименовать или изменить, скопировать, создать, удалить, в корзину.
- Не понял назначение инструмента — по умолчанию в deny и скажи об этом.

**Дополнительно, отдельным «да»**: allow для чтения и поиска в Gmail, Calendar, Drive и для создания черновика Gmail — тогда планёрка и разбор почты не будут спрашивать разрешение на каждое чтение.

Покажи правила как JSON:

```json
{
  "allow": ["mcp__…__crm_reference", "…"],
  "ask": ["mcp__…__crm_confirm"],
  "deny": ["mcp__…__send_message", "…"]
}
```

Затем — предпросмотр без записи:

```bash
osascript -l JavaScript "${CLAUDE_SKILL_DIR}/merge-permissions.js" plan '<JSON одной строкой>'
```

Скрипт принимает только точные имена MCP-инструментов. В ответе — файл, что добавится (`added`) и конфликты (`conflicts`). Покажи это и спроси: «Записать эти правила в ~/.claude/settings.json? Сначала сделаю копию файла, остальные настройки не трону. Ответьте «да»».

## 3. Запись — только после «да»

1. Тот же JSON:
   ```bash
   osascript -l JavaScript "${CLAUDE_SKILL_DIR}/merge-permissions.js" apply '<JSON одной строкой>'
   ```
   Скрипт копирует файл в `settings.json.bak-<дата-время>`, добавляет только новые правила, остальные ключи не трогает и проверяет, что JSON читается.
2. Покажи: сколько правил добавлено и путь копии. Откат: `cp "<путь копии>" ~/.claude/settings.json`.
3. Конфликты объясни: запрет (deny) сильнее вопроса (ask), вопрос сильнее разрешения (allow). Правило, которое уже стоит в deny, человек при желании убирает сам.
4. Дополнительный блок (чтение коннекторов) — отдельно: показать, `plan`, «да», `apply`.
5. «Перезапустите Claude Code командой из README, чтобы правила точно применились».

Не правь `settings.json` руками и не пиши туда ничего, кроме этих правил. Человек сказал «нет» — ничего не записывай и коротко скажи, что помощник будет спрашивать разрешения по ходу работы.
